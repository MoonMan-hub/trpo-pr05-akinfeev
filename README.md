# Практическая работа №5. PHP ООП: классы, конструкторы и модели предметной области

Дисциплина: Технологии разработки программного обеспечения.

## Что сделано

PHP-приложение «Каталог товаров». Данные читаются из `data/products.json` и `data/categories.json`,
из них создаются объекты `Product` и `Category`. Страница показывает карточки товаров,
статистику (количество, средняя цена, сколько доступно) и форму фильтра по категории.
Также на странице есть блок, который проверяет, что конструктор `Product` отклоняет плохие данные.

Технологии: PHP 8.0+, HTML, CSS. Библиотеки и composer не нужны.

## Требования

## Схема

```
products.json + categories.json
          |
          v
   CatalogService  ---- создаёт ---->  Product, Category
   (читает JSON, фильтрует,            (хранят данные, проверяют их
    считает среднюю цену)               в конструкторе, умеют отвечать
          |                             на вопросы о себе)
          v
      index.php
   (получает объекты, обрабатывает форму фильтра,
    выводит HTML и экранирует значения)
```

Ответственность:

- **Product** - один товар: хранит `id`, `name`, `price`, `categoryId`, `active`, проверяет их в конструкторе, имеет методы `isAvailable`, `belongsToCategory`, `getFormattedPrice`, `isExpensive`, `getPriceWithDiscount`.
- **Category** - одна категория: `id` и `name`, метод `hasProduct`. Связь с товаром идёт через `categoryId`.
- **CatalogService** - читает JSON, создаёт объекты, пропускает плохие строки (сообщения в `getErrors()`), фильтрует по категории, считает среднюю цену и количество доступных.
- **index.php** - единственное место, где есть HTML. Модели и сервис ничего не выводят.

## Свойства классов (по class_requirements.csv)

| Класс | Свойство | Тип |
|-------|----------|-----|
| Product | id | int |
| Product | name | string |
| Product | price | float |
| Product | categoryId | int |
| Category | id | int |
| Category | name | string |

Дополнительно у `Product` есть необязательное свойство `active` (bool, по умолчанию `true`).
Оно есть в `products.json` и нужно для метода `isAvailable()` и статуса «доступен / нет в наличии».

## Обработка ошибок

- Конструкторы `Product` и `Category` бросают `InvalidArgumentException` (пустое имя, цена < 0, id <= 0).
- Если в JSON плохая строка, она пропускается, а на странице появляется жёлтый блок с причиной.
- Нет файла или сломан JSON: страница показывает красный блок с ошибкой.
- Неизвестная категория в фильтре: сообщение, показываются все товары.
- Пустой результат фильтра: текст «Товары не найдены».
- Все значения выводятся через `htmlspecialchars`.

## Почему ручные require_once неудобны

Сейчас в `index.php` три `require_once`. Когда классов станет 30-50, придётся:

- вручную добавлять строку для каждого нового класса и помнить про порядок подключения;
- править пути, если папки переименовали или файлы переместили;
- повторять списки подключений в каждой точке входа.

Поэтому в больших проектах используют автозагрузку (`spl_autoload_register`, PSR-4 и composer):
PHP сам находит файл класса по его имени.
